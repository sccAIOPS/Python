# Task Completion Checklist

When completing a task (adding or modifying code), follow this checklist:

## 1. Code Quality Checks

### Run Doctests
```bash
python3 -m doctest -v <your_file.py>
```
Ensure all doctests pass before proceeding.

### Run Linting (Ruff)
```bash
ruff check <your_file.py>
ruff format <your_file.py>
```

### Run Type Checking (Mypy)
```bash
mypy --ignore-missing-imports <your_file.py>
```

## 2. Pre-commit Validation
Run all pre-commit hooks:
```bash
pre-commit run --all-files --show-diff-on-failure
```

This will automatically check:
- ✅ Executables have shebangs
- ✅ TOML/YAML validity
- ✅ End-of-file fixes
- ✅ Trailing whitespace
- ✅ Ruff linting and formatting
- ✅ Codespell (spell checking)
- ✅ Mypy type checking
- ✅ Filename validation

## 3. Content Verification

### For New Algorithms
- [ ] File named with `snake_case.py`
- [ ] Functions have descriptive names (no abbreviations)
- [ ] All functions have type hints
- [ ] All functions have docstrings with doctests
- [ ] Doctests cover: normal cases, edge cases, error cases
- [ ] Algorithm returns results (doesn't print)
- [ ] No `input()` calls
- [ ] External libraries only if necessary
- [ ] `__init__.py` updated if new directory created

### For Bug Fixes / Modifications
- [ ] Original doctests still pass
- [ ] New test cases added if relevant
- [ ] No unintended changes to other code
- [ ] Type hints preserved/updated

## 4. Files NOT to Modify
- `README.md` - Auto-generated
- `DIRECTORY.md` - Auto-generated by GitHub Actions

## 5. Final Steps
```bash
# Verify everything passes
pre-commit run --all-files

# If all passes, commit
git add <your_files>
git commit -m "feat: Add <algorithm_name> algorithm"
```

## 6. Pull Request Checklist
When submitting a PR:
- [ ] Tests pass on GitHub Actions CI
- [ ] No merge conflicts
- [ ] Descriptive PR title and description
- [ ] Add `Fixes #<issue_number>` if fixing an issue
- [ ] Follow commit message conventions
